hookus-pocus

MSc thesis, OPIT

A small multi-agent team for project management (triage, specs, review, status reports) where the model writes and plain code decides. Every ticket change passes one action gate with per-role permissions, deterministic Python hooks, human confirmation for high-impact actions, and ticket text kept apart from instructions. Each guardrail can be switched off, so a benchmark measures what it is worth: forbidden actions blocked rise to 1.00 from a baseline of 0.35 to 0.42, and end-to-end prompt injection success drops to 0.00 across three models (pilot runs).

Principles

Computable ground truth should be computed, not delegated to a model.
  • Deterministic where it matters. Financial figures in Business Plan AI are re-derived by pure Python. In hookus-pocus, plain-code hooks, not the model, decide which ticket actions are allowed.
  • Guardrails you can measure. Every safety feature in hookus-pocus can be switched off, so a benchmark shows what each one is worth instead of assuming it.
  • Humans stay in the loop. High-impact agent actions wait for an explicit yes, and the WhatsApp Toolkit asks before sending when the recipient match is uncertain.
  • Honest failure over confident fiction. Sherpa falls back to conversation when no source clears the retrieval threshold. Non-convergent plans ship with a manual-review banner.
  • Metrics on the hard corpus. 62% mAP50 is reported on the full heterogeneous test set, not a narrower favourable slice.
  • Local-first by default. Ollama and LM Studio inference, Milvus snapshots, on-device pipelines. Data stays where it belongs.
